# ADR 0011: Відмова від Husky на користь `git config core.hooksPath`

* **Статус:** Прийнято (Accepted)
* **Дата:** 28.09.2026

## Контекст (Context)
Для забезпечення якості коду, перевірки типів та автоматичного форматування перед комітами та пушами в проєкті використовуються Git-хуки (`pre-commit`, `pre-push`).

Раніше для керування хуками використовувалася бібліотека **Husky**. Проте в процесі експлуатації було виявлено ряд недоліків:
1. **Зайві залежності (Dependency Overhead):** Husky додає додаткові пакети у `devDependencies` та складність у `package.json`.
2. **Зміни у версіях та підтримка:** Часті мажорні оновлення Husky (v4 -> v6 -> v9) змінювали синтаксис та підходи до налаштування, що вимагало додаткових витрат часу на міграції.
3. **Прив'язка до Node.js / npm:** Управління хуками через Husky орієнтоване на Node-екосистему, хоча самі Git-хуки є внутрішнім механізмом Git і мають бути незалежними від інструментарію конкретної мови програмування.

Починаючи з версії Git 2.9 (випущеної у 2016 році), Git надає вбудовану можливість вказувати кастомну директорію для хуків через команду `git config core.hooksPath <path>`.

## Рішення (Decision)
Ми приймаємо рішення **повністю відмовитися від використання Husky** на користь нативного механізму Git `core.hooksPath`.

### Кроки реалізації:

1. Видалити пакет `husky` з `devDependencies` та прибрати директорію `.husky`.
2. Створити директорію `.githooks/` у корені репозиторію та помістити туди необхідні скрипти (наприклад, `.githooks/pre-commit`).
3. Зробити скрипти виконуваними (`chmod +x .githooks/*`).
4. Інтегрувати налаштування хуків у командний файл проєкту (`Makefile`):

```makefile
prepare:
	npm install
	git config core.hooksPath .githooks
```

5. Оновити документацію проєкту (`README.md`), додавши рекомендацію запускати `make prepare` після первинного клонування репозиторію.

## Наслідки (Consequences)

### Позитивні:
* **Нульовий обсяг залежностей (Zero-dependency footprint):** Відсутність додаткових npm-пакетів для роботи Git-хуків.
* **Простота та прозорість:** Скрипти хуків є стандартними shell-скриптами, розміщеними в `.githooks/`, без проміжних abstractions чи Husky-врапперів.
* **Продуктивність:** Запуск хуків здійснюється напряму Git без додаткового оверхеду на завантаження Node-модулів Husky.
* **Уніфікований сетап:** Команда `make prepare` стає єдиною точкою входу для підготовки робочого середовища (встановлення npm-пакетів + конфігурація git hooks).

### Негативні / Ризики:
* **Необхідність ручного/командного ініціалізації:** На відміну від автоматичного `prepare`-скрипта npm, який міг тригерити Husky, розробники мають один раз виконати `make prepare` (або `git config core.hooksPath .githooks`) при ініціалізації проєкту.
  * *Мітигація:* Додати чітку інструкцію у розділ «Getting Started» в `README.md` та сповістити команду про новий процес підготовки середовища.
