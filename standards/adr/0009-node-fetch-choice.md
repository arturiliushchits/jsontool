# 0009. Вибір нативного fetch

* **Статус:** Прийнято (Accepted)
* **Дата:** 2026-09-28

## Контекст (Context)
Необхідно здійснювати HTTP-запити як на серверній стороні (Node.js), так і у клієнтському коді.

## Рішення (Decision)
Використовувати нативний **`fetch`** (глобальний Web API) замість сторонніх бібліотек на кшталт `axios`.

Обґрунтування:
* Мінімізація сторонніх залежностей, що підвищує безпеку проєкту.
* Використання єдиного стандартного Web API як на сервері, так і в клієнтському Vanilla JS коді.

## Наслідки (Consequences)
* **Позитивні:**
  * Єдиний синтаксис та стандарт для сервера й клієнта.
  * Відсутність сторонніх залежностей.
* **Негативні / Ризики:**
  * Відсутність деяких обгортальних можливостей `axios` (наприклад, автоматичної обробки HTTP-помилок та зручних interceptors "з коробки").
