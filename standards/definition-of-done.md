# Definition of Done (DoD) — JSON Tool

Цей документ визначає критерії якості та готовності кожної фічі чи модулю перед включенням до основної гілки проєкту.


## 1. Функціональна відповідність

* [ ] Усі вимоги з `spec.md` для конкретного модуля реалізовані у повному обсязі.
* [ ] Основні можливості (підсвітка синтаксису, валідація схеми, перевірка JSON, візуальне редагування метаданих, Flat View, Експорт в MD, Share-посилання) працюють без збоїв.
* [ ] Збереження та відновлення з історії працює коректно через SQLite.


## 2. Архітектура та Паттерни Проектування

* [ ] **Strategy**: Модуль експорту чітко розділений на окремі стратегії (`MarkdownExportStrategy`, `JsonExportStrategy`).
* [ ] **Command**: Зміни стану схеми інкапсульовані в об'єкти команд з підтримкою скасування.
* [ ] **Template Method**: Валідація дотримується фіксованого алгоритму (`parseJson` $\rightarrow$ `validateRules` $\rightarrow$ `formatErrors`).
* [ ] **Flyweight**: Спрощення розробки шляхом перевикористовування UI-компонентів (за схожим принципом до React-classes).
* [ ] **Observer**: Події редактора розсилаються підписникам без прямого жорсткого зв'язування модулів.


## 3. Філософія та Якість Коду

* [ ] **Minimal Code First**: Код написаний максимально лаконічно, без відсутніх або надлишкових абстракцій/бібліотек.
* [ ] Відсутній несистематизований або «мертвий» код (Unused imports, commented code).
* [ ] Іменування змінних, методів та класів зрозуміле й виражає намір (Self-documenting code).


## 4. Тестування

* [ ] Покрито модульним тестуванням (Unit tests) реалізації всіх 5 паттернів.
* [ ] Написано інтеграційні тести для API ендпоінтів (`/api/schemas`, `/api/export`).
* [ ] Усі тести проходять успішно при виконанні `make test`.


## 5. Документація та Стандарти

* [ ] Оновлено `standards/spec.md`, якщо під час розробки внесено узгоджені зміни.
* [ ] Лог промптів AI зафіксовано у `/ai/prompts-log.md`.
* [ ] Сесії розробки задокументовано у `/ai/sessions/`.
* [ ] `README.md` містить актуальні інструкції із запуску.
